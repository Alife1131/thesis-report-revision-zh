# 报告与 Word 核验

1. 记录实际选用的报告、原稿、输出文件名。相似文件名中有“(1)”时，优先使用用户指定的文件。打开报告图例，记录本次纳入的等级及其标识。历史 PaperPass 文件曾使用 F12828、F39800、9D91E9；这些是历史样本，维普或新版报告要重新核对。颜色也可能来自高亮、底纹或样式。
2. 按连续标记范围提取原话，附章节和上下文。Word 经常把一个句子拆进多个文字片段，先还原可读句再定位。纯空格、插图占位和报告说明排除。把查找用的规范化字符位置映射回原始字符位置，特别留意引用上标和全角括号。匹配歧义时记录候选位置。
3. 为每处保存一条工作记录：章节、原稿段落、标记起止、原句、改句、受保护的内容。以原稿文本再次核对后再写入。只标中段时，前缀和后缀应逐字相同。跨句改写时先确认所有受影响文字在授权范围内。
4. DOCX 文件里一个段落可以混排宋体、英文、上标和域。对原有文字节点做局部替换，在风格边界处分开处理；引用、书签、超链接、域和图片锚点原样保留。替换完成后重新抽取段落文字，与拟定改稿比对。
5. 将原稿和输出作为两个独立文档读取。对每个非目标段落逐字比较；比较段落属性、字符属性、分节设置和图片位置。纯文字修改时，检查媒体、页眉页脚、样式、编号、作者属性等部件内容一致。抽取图号与引用时覆盖“图2- 1”、组合引用“[16,17]”等原稿实际写法。要求保留标点序列时逐字符比较，同时核对数字、单位和数值的含义。
6. 输出先写入独立文件，重新打开验证。若要覆盖，确认原稿自定位后没有新编辑，再替换。使用 WPS 或 Word 查看有明显长度变化或紧邻图片的页面；如只完成结构检查，交付时说明实际检查范围。目录域刷新、改分页、调字号均属于另行排版工作，按本次授权处理。

验收例：同一段有两句，报告仅标第二句，第一句含“图3-5”，第二句末尾有上标[19]。通过条件是第一句逐字相同、第二句保留[19]及上标属性、图号仍引用原图、其他段落及嵌入图片一致。即使整段读起来更流畅，改动第一句也属于越界。

本流程参考本项目“初版v2.2.2”的实际脚本。该脚本检查标记段落集合、标点序列、图号引用以及段落与格式差异。使用时须按当前报告定位，避免沿用历史段落编号。
